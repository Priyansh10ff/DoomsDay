## QA (same as batch 1)

Static structure, WAD-sector search and room-graph search (must agree), for keyed
stages exit unreachable without the key and key room off the start->lock path, and one
ViZDoom engine check per map (spawn, sector count, object classes, locked door refuses
then opens with the key, exit ends the level). Maps that fail are deleted and logged.

## What changed in the generator inputs

`maps/gen_config.json` and `GEN_VERSION` (0.1.1) are **unchanged**, so batch-1, val and
held-out maps still regenerate byte-identically. Batch 2 uses `maps/gen_config_b2.json`,
a copy with these train-side changes:
- `loop_prob` 0.35 -> 0.6, `max_loops` 1 -> 2 (batch 1: 4 of 120 maps had a loop);
- `rooms` S0/S1 [3,6] -> [3,8], S2/S3 [4,7] -> [4,8].

Variety obtained: maps with at least one loop corridor, batch 1 train 2/80, batch 2
51/700 (7%; 3 with two loops). Loops stay rare because a loop needs two same-side
rooms facing each other within the corridor length and floors within 24 units.
Room counts batch 2: 3:65, 4:113, 5:110, 6:144, 7:135, 8:133 (batch 1: 3-7, none with 8).

Not widened: room size, corridor length/width, themes (themes partition the splits).
Note: the train room-count range now overlaps the held-out range (held-out S0/S1 [4,8],
S2/S3 [5,9]), so held-out room counts are no longer strictly larger than train's,
except S2/S3 with 9 rooms. Room size [5,17], corridor length up to 8, corridor width 4
and the held-out themes remain held-out-only.

Map diagonals: batch 1 889-2717 units (mean 1720); batch 2 879-3408 (mean ~1880),
19 maps above 2717. `configs/a0_env.py` (`GENERATED_MAPS.episode_timeout_tics` 4200)
was sized from the batch-1 range; owner `worker` should check whether the time limit is
enough for the largest batch-2 maps.

## Bundle and selection

- `maps/bundles/train-all-b2.wad`: 780 maps, lumps DD0000-DD0779. DD0000-DD0079 are the
  batch-1 maps in `train-all` order; batch 2 follows in stage then seed order.
- `train-all` (80 maps) and its WAD are unchanged (asserted by `finalize` and tests), so
  old runs and resumes still work. A resume on a different bundle is refused by
  `train/curriculum_vec_env.py` (bundle hash check).
- Selection: environment variable `DOOMSDAY_TRAIN_BUNDLE=train-all-b2`. Read by
  `maps.loader.training_bundle()` (used by `teachers/collect.py`, `tools/env_bench.py`)
  and by `CurriculumScheduler.from_bundle()` (used by `train.run_doom --maps generated`),
  where it overrides `curriculum/config.json` `bundle_id`. Unset = `train-all`.
  No file in `teachers/` or `train/` was edited.
- Lump limits: names stay `DD` + 4 digits (valid up to 10,000 maps). Tests load
  DD0000, DD0390 and DD0779 through `DoomEnv` on the generated-maps training config and
  check sector count and spawn point against that member's own WAD.

## Safety of the old build path

`python -m maps.build` deletes and rewrites every split. It now refuses (exit 2) when
`splits.json` lists batch-2 maps, unless `--discard-batch2` (tested on a temp copy).
`finalize` reads every batch-2 log regardless of date, refuses to drop listed batch-2
maps, and re-running it reproduced the same bundle hash.
