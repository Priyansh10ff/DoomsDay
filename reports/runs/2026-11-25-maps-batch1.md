## Validation

- **Generation failures:** 0, so no seed exhausted its 12 attempts. Some maps needed attempt > 0; this is recorded per map.
- **Batch 0.1.0** was rejected by QA on 3 maps: S3-train-103006, S2-val-502005, S3-val-503002, all "exit reachable WITHOUT the key".
  - Cause: the "at least one normal door" rule could overwrite the locked door.
  - Fixed in 0.1.1, and all maps were regenerated.
- **Batch 0.1.1:** 120 of 120 passed. Per map, the checks were:
  - static structure;
  - WAD-sector search and room-graph search, which agree;
  - for keyed stages, the exit is unreachable without the key and the key is off the start-to-lock path;
  - the engine check: spawn, sector count, object classes, locked door refusal and opening, exit.

## Random-action rollouts (200 decisions, DoomEnv)

- 14 maps were run: 3 per stage from train, 1 heldout S3 through `EVAL_CONFIG`, and 1 val S2.
- Results:
  - 0 crashes;
  - all observations finite;
  - no episode ended (a random policy reaches no exit in 200 decisions).
- Entities seen:
  - `monster` on 1 of 3 S3 train maps;
  - keys on S2-train-102002 and S3-train-103001;
  - ammo and health on S3 maps.
- The heldout and val samples saw only `decoration`.
- `decoration` appears about 120 times per rollout even on empty S0 maps. These are probably the agent's own bullet puffs (R2.4: BulletPuff is typed decoration); not investigated.

## Weaknesses

- Only 4 of 120 maps have loop corridors, so layouts are mostly trees.
- Walls are axis-aligned only.
- Monster types are Zombieman, ShotgunGuy and Imp only.
- One player start per map.
- All promotion thresholds in `curriculum/config.json` are unmeasured.

## Changes needed outside maps/ and curriculum/ (not made)

**worker (`train/`): per-episode curriculum map choice.** No env change is needed: `DoomEnv.reset(options={"map": lump})` already switches maps inside one PWAD (probe A2).

1. **Training config.** Use `TRAIN_CONFIG.replace(scenario_wad=None, map_wad=<bundle path from maps.loader.training_bundle()>, maps=tuple(all lumps), engine_rewards=VANILLA_ENGINE_REWARDS)`.
2. **`train/vec_env.py:74`.** `step_autoreset(env, action)` calls `env.reset()` with no options. That draws uniformly from `cfg.maps` and **bypasses the curriculum**.
   - Add a `reset_options` argument and call `env.reset(options=reset_options)`.
   - `SyncVecEnv.reset/step` and `SubprocVecEnv` (worker loop near `subproc_vec_env.py:69` and its step command) must carry one options dict per env.
3. **Main process.** Keep one `CurriculumScheduler.from_bundle()`.
   - For each env, hold the choice for its *next* episode and send `{"map": choice.lump}` with the step.
   - On episode end, call `scheduler.record(choice, success=final_infos[i]["level_exit"])`, then issue a new choice.
   - Several choices may be pending at once.
4. **Resume.** Store `scheduler.state_dict()` in the checkpoint.

**env-engineer / advisor: where val maps live.** `EVAL_CONFIG.assert_vanilla` refuses any `map_wad` under `maps/`, so val maps (`maps/val/`) currently run on a TRAIN-type config with no mods. This is a question for `advisor`. The options:
- allow `maps/val/` in `TRAINING_MAP_DIRS` exemptions;
- move val to a new top-level `val_maps/`.

**Rule conflict on Freedoom Phase 1.**
- `maps.loader` refuses Phase 1 in training: the role rule is that Freedoom is evaluation-only.
- ADR 0005 allows Phase 1 in the last rung.
- `env.config.assert_trainable` does not refuse Phase 1 (`iwad="freedoom1"`).
- Advisor should decide which rule stands.
