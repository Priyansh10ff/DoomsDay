# Spatial memory: Neural Map, Active Neural SLAM, MERLIN, recurrent baselines

Date: 2026-11-25. Author: `research` subagent. Feeds ADRs on spatial memory and model architecture.

How sources were read, and limits:
- arXiv PDFs could not be parsed, so papers were read through the ar5iv HTML rendering, queried through a small extraction model that returned quotes. I did not read the pages end to end myself.
- The MERLIN page was read only for its first 100,000 of 127,188 characters, so appendix details (memory row count, learning rates) may exist but were not seen.
- The rendering sometimes doubles digits; numbers here were not visibly affected unless flagged.
- Venues are given only where the arXiv abstract page states them.
- No fetched page contained instructions aimed at the agent.

Target hardware for "reachable?" verdicts: 24 CPU threads, 15.4 GB RAM, one RTX 5060 laptop GPU.

## 1. Summary

- **Structured, position-indexed memory beat plain LSTM on maze navigation, including unseen mazes, at small training budgets.** Neural Map on ViZDoom mazes: 66.6% success on unseen maps versus 52.4% for LSTM, trained for up to 7 million frames with 16 environments. That budget is reachable here.
- **Every map-style memory needs to know where to write.** Neural Map takes the agent's (x, y) from the game ("oracle"); its ego-centric variant needs only velocity but was described without experiments. Active Neural SLAM estimates pose from noisy odometry with a supervised pose estimator. For us, absolute coordinates in the policy are forbidden, so the write address would have to come from ego-motion, with the map kept in the agent's frame. That specific configuration has thin published evidence.
- **Active Neural SLAM's result comes from a modular pipeline that includes a classical planner.** It uses the Fast Marching Method to turn the global goal into short-term goals, and its local policy is trained by behavioural cloning. The planner is barred by rule 4.1. Ideas that remain usable: a learned egocentric obstacle/explored map trained with ground-truth labels, and a map-conditioned policy that picks long-term goals every 25 steps, rewarded by coverage increase.
- **MERLIN's lesson is about how memory is trained, not its shape.** Its authors report that memory trained only through the RL gradient fails on tasks with long delays, and that training the memory writer with a predictive objective fixes this. The agent itself (192 worker threads) is not reachable, but an auxiliary predictive loss on the memory is.
- **Plain recurrent policies are the cheap baseline.** In each comparison opened here the LSTM/GRU-only agent scored below the structured-memory agent (Neural Map tables, ANS baselines, MERLIN, FeUdal water maze). Procgen found LSTM roughly equal to frame stacking on tasks that need little memory. No source opened here tests any memory on a keycard-then-door backtracking task in Doom; that is a gap.

## 3. Reusable hyperparameters, architecture details, compute

### Neural Map (Parisotto and Salakhutdinov; https://ar5iv.labs.arxiv.org/html/1702.08360)
- Map: 15x15 x 32 channels (2D mazes); 32 channels x 9x9 (Doom).
- Operators: global read (3-layer CNN over the map), context read (content-based addressing over cells), local write at the agent's cell, GRU-style gated write; combined with an LSTM in 3D.
- Position: quantized game coordinates (not allowed for us) or ego-centric shifting by velocity (allowed, untested in the paper).
- Training: synchronous multi-env actor-critic (A3C-derived), 16 environments; 160M total steps (2D), up to 7M frames (Doom). Learning rate and discount values not found.
- Compute verdict: reachable. A 9x9 to 15x15 x 32 map is tiny; the cost is backpropagation through the map over time (my inference).

### Active Neural SLAM (Chaplot et al.; https://ar5iv.labs.arxiv.org/html/2004.05155)
- Map: 2 channels (obstacle, explored) at 5 cm cells, 480x480 for training; inputs RGB 128x128 plus 3-dim odometry.
- Neural SLAM module: supervised, Adam lr 1e-4, BCE (map) + MSE (pose).
- Global policy: PPO, lr 2.5e-5, gamma 0.99, entropy 0.001, value loss 0.5, 36 mini-batches, 4 epochs; new long-term goal every 25 steps; reward = coverage increase (scaled by 0.02).
- Local policy: recurrent, behavioural cloning (BCE), Adam lr 1e-4.
- Budget: 10M frames, 72 parallel scenes. GPU model not stated.
- Compute verdict: the frame budget is reachable; the published pipeline is not usable because of the FMM planner (rule 4.1).

### MERLIN (Wayne et al.; https://ar5iv.labs.arxiv.org/html/1803.10760)
- Memory-based predictor trained by a variational lower bound; policy gradient blocked from the memory writer; retroactive memory update ("storing each state variable together with a representation of the events that occurred after it in time"); three read heads in navigation tasks; unroll 20.
- 192 worker threads. Row count, widths, learning rates: not found in the part read.
- Compute verdict: not reachable as a system; the principle (an auxiliary predictive loss shapes memory) is cheap to adopt.

### Recurrent baseline (Sample Factory; https://ar5iv.labs.arxiv.org/html/2006.11751)
- GRU 512, rollout length 32, lr 1e-4, batch 2048.

## 4. Recommendations for advisor

1. **The best-supported custom memory that fits the rules is an ego-centric, write-at-agent grid memory (Neural Map style, addressed by ego-motion and never by absolute coordinates) beside a GRU core, not a GRU alone.** Rests on the Neural Map result rows (2D and Doom unseen maps), the "paired with an LSTM" row and the recurrent-only row. Strength: strong that grid memory beats LSTM on unseen mazes at a reachable budget (7M to 160M frames); **weak for the ego-centric form specifically**, which the paper describes but does not test, and none of it was shown with combat or doors. A GRU-only agent should be kept runnable as the comparison.
2. **Do not adopt the Active Neural SLAM pipeline; the reusable ideas are (a) a learned egocentric obstacle/explored map trained with engine ground truth as training-only labels and (b) a learned policy that selects goals on that map at a slower timescale, rewarded by coverage.** Rests on the ANS result, planner, training, ablation and supervision rows. Strength: strong that explicit maps with a goal-setting policy out-explore flat recurrent RL in unseen layouts at 10M frames; strong that the published system violates rule 4.1 (FMM planner); **no evidence** for performance once the planner is replaced by a learned goal-reaching policy, which is a research risk the ADR should name.
3. **Whatever memory is chosen, the evidence supports adding a training-only auxiliary predictive loss on it (for example predicting local occupancy, or key/door features seen earlier, from memory), because RL gradients alone are reported to be insufficient over long delays.** Rests on the MERLIN rows and the ANS supervision row, with the Arnold game-features result in `vizdoom-agents.md` as Doom-specific support for auxiliary targets. Strength: strong qualitative evidence from MERLIN (no numeric table extracted; partial read) and strong supervised-mapper evidence from ANS; no source tests this on Doom keycard/door tasks.
