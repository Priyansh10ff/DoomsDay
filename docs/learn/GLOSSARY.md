# Glossary

Alphabetical. Each entry gives a one-sentence definition and the lesson where the term was first introduced. Entries are added, not removed; a definition is corrected only when the code changes and makes it wrong (marked "corrected" with the date).

- **1D convolution**: a layer that slides a small window of learned weights along a sequence (here, the 80 ray columns), so the same pattern is recognised anywhere along it. (Lesson 04)
- **Ablation**: an experiment that switches one piece off to measure what that piece contributes; ADR 0005 plans one with and without the coverage bonus. (Lesson 12)
- **ACS**: DOOM's built-in map scripting language, which a map file can carry to change how the level behaves (for example opening doors automatically); allowed in training only. (Lesson 01)
- **Action**: the agent's choice of what to do next; for us, one index for each of six button groups. (Lesson 01)
- **Action space**: the description of every action the environment accepts; ours is `MultiDiscrete([3, 3, 7, 2, 2, 2])`. (Lesson 01)
- **Adam**: the optimizer we use; it turns gradients into weight changes, adapting the step size per weight. (Lesson 07)
- **Advantage**: how much better an action turned out than the value guess expected; positive means "do this more". (Lesson 06)
- **Agent**: the thing that chooses actions; here, our neural network plus the code that picks a button choice from its output. (Lesson 01)
- **Anneal**: shrink a number gradually during training; the coverage coefficient falls from 0.25 to 0.05 over 60,000 per-environment decisions. (Lesson 12)
- **Argmax**: picking the option with the largest value (here, the most likely option of a head). (Lesson 05)
- **Arm**: one variant of an experiment that changes exactly one thing from the base, so its effect can be measured on its own. (Lesson 09)
- **atan2**: a math function that turns a position difference into an angle; computing aim this way is a banned "aimbot", and it appears nowhere in our observation code. (Lesson 02)
- **Atomic replace**: replacing a file in one operating-system step, so a reader sees either the whole old file or the whole new one; `save_checkpoint` uses it. (Lesson 12)
- **Attention**: a layer in which each item computes a weighted average over a set of items, with weights from how well its query matches each item's key. (Lesson 04)
- **Auto-reset**: the vectorized environment resets an environment as soon as its episode ends, returning the new episode's first observation and keeping the ended one aside as the final observation. (Lesson 06)
- **Auxiliary head / auxiliary loss**: an extra network output trained to predict a training-only label (keys held, damage soon, visible monsters) to shape the memory; it is never used to choose actions. (Lesson 05)
- **Available memory**: how much memory the whole system still has free; the memory watcher stops a run when it falls below 1.5 GiB. (Lesson 08)
- **Backpropagation through time**: computing gradients back through every step of a recurrent network's sequence, so the memory learns what to keep. (Lesson 07)
- **Baseline**: the result of a simple reference that "learning" must beat; for the first run, a policy that presses random buttons. (Lesson 10)
- **Binary cross-entropy (BCE)**: the standard loss for yes/no predictions; small when the predicted probability is close to the true 0 or 1. (Lesson 07)
- **Body frame**: describing a movement relative to the player's own body (forward, left, up) instead of along the map's axes. (Lesson 02)
- **Bootstrapping**: using the network's value guess in place of rewards that were not observed (after the rollout ends, or after a time-out). (Lesson 06)
- **Buffer**: an image-sized array the engine fills on each rendered frame, such as the screen, depth or labels buffer. (Lesson 01)
- **Categorical**: a choice from a fixed, short list of options (as opposed to a continuous number); a categorical distribution gives a probability to each option. (Lesson 03)
- **Ceiling effect**: when every option scores near the maximum, so a test cannot tell them apart. (Lesson 09)
- **Cell (coverage grid)**: one square of the fixed 128 x 128 map-unit grid laid over the map's x/y plane; heading and height are not part of it. (Lesson 12)
- **Checkpoint**: a saved copy of the training state (weights, optimizer, return scale, configs, sensor signature) that can be loaded later. (Lesson 06)
- **Child process**: a process started by another process; our workers are children of the main process, and each engine is a child of a worker. (Lesson 08)
- **Clip fraction (`clipfrac`)**: the share of stored steps whose probability ratio had already moved outside PPO's allowed range (0.8 to 1.2) during an update; low means gentle updates. (Lesson 11; first used in Lesson 07)
- **Coefficient (intrinsic)**: the number the raw coverage bonus is multiplied by before it is added to the reward (`intrinsic_coef`). (Lesson 12)
- **Concatenate**: join several lists of numbers side by side into one longer list, as the fusion step does with the encoder outputs. (Lesson 04)
- **Cooldown**: a deliberate pause between training updates, set by `cooldown_s`; the user's throttle besides the number of workers. (Lesson 08)
- **Coverage bonus (episodic)**: our intrinsic reward: the first time in an episode the player stands in a new cell it pays 1/64, for at most 64 cells, so at most 1 raw per episode. (Lesson 12)
- **Curriculum**: a planned sequence of training situations, usually from easier to harder. (Lesson 01)
- **Daemon process**: a child process that Python ends automatically when the main process exits. (Lesson 08)
- **Delta button**: a ViZDoom button that takes a number instead of on/off; `TURN_LEFT_RIGHT_DELTA` takes degrees per tic. (Lesson 03)
- **Dense signal**: a training signal present at every step (for example the value loss); a sparse signal appears only at some steps (for example the answer in the toy task). (Lesson 09)
- **Depth buffer**: a 120x160 image where each pixel says how far away the surface at that pixel is (0 to 255, bigger is farther, about 8 map units per step). (Lesson 01)
- **Detach**: cut the gradient path at a point, so a loss cannot change anything before it. (Lesson 09)
- **Deterministic policy**: a policy that always picks the same action in the same situation; its entropy is 0. (Lesson 11)
- **Dict space**: a Gymnasium observation description made of several named arrays, each with a fixed shape, type and range. (Lesson 01)
- **Discount factor (γ, gamma)**: the number just below 1 that makes rewards further in the future count less; ours is 0.997. (Lesson 06)
- **Double pay**: the same game event paid twice, once by the scenario's own reward and once by our terms; `check_reward_setup` refuses such setups. (Lesson 12)
- **Edge-triggered**: a button that acts only at the moment it goes from up to down, not while it is held; DOOM's USE is edge-triggered. (Lesson 03)
- **Ego-motion**: the agent's own movement described from its own point of view: forward speed, sideways speed, vertical speed and how much it turned since the last step. (Lesson 02)
- **Embedding**: a learned lookup table that turns a whole number (such as an entity type id) into a short list of learned numbers. (Lesson 04)
- **Encoder**: a piece of the network that turns one kind of raw input into a list of numbers the rest of the network can use. (Lesson 02)
- **End-to-end throughput**: decisions per second counting both collecting experience and updating the network. (Lesson 10)
- **Engine reward**: a reward ViZDoom computes inside the game, such as `map_exit_reward`; EVAL allows only +1 for reaching the exit. (Lesson 01)
- **Entity**: one visible thing that is not a wall or floor: a monster, a projectile, a pickup, a key, a decoration, a hazard. (Lesson 02)
- **Entity mask**: a true/false array saying which of the 24 entity rows hold a real entity and which are padding. (Lesson 02)
- **Entity set**: the list of currently visible entities, which changes length from step to step; stored as 24 rows plus a mask. (Lesson 02)
- **Entropy**: a measure of how spread out a probability distribution is; 0 when one option is certain, largest when all are equally likely. (Lesson 05)
- **Entropy collapse**: the policy's entropy falling close to 0, so it stops trying different actions; "premature" when this happens before a good behaviour has been found. (Lesson 11)
- **Entry point**: the script you run to start training; ours is `python -m train.run_doom`. (Lesson 08)
- **Environment**: everything the agent interacts with; here, DOOM seen through our `DoomEnv` wrapper. (Lesson 01)
- **Environment factory**: a small picklable object that builds a new environment when called; it is sent to a worker process and called there. (Lesson 12)
- **Episode**: one play-through, from the start of a level until death, level exit or time-out. (Lesson 01)
- **Epoch**: one pass of the update over the stored rollout; we use 3. (Lesson 07)
- **EVAL config**: `EVAL_CONFIG`, the settings that match the judges' conditions (stock game data, vanilla rules, no mods); it refuses to start if any rule field is not vanilla. (Lesson 01)
- **Exit code**: the number a program returns when it ends; 0 means success, other values name a kind of failure (the training entry point uses 2 and 3). (Lesson 08)
- **Explained variance**: a diagnostic of how well the value guesses predicted the returns; 1 is perfect, 0 is no better than a constant. (Lesson 06)
- **Extrinsic reward**: reward for something that happens in the game itself (an exit, a key, damage, death, time). (Lesson 12)
- **Factorized**: describing a joint choice as independent separate choices, so its probability is the product of the parts; our six heads form a factorized distribution. (Lesson 05)
- **Field groups**: the four kinds of `EnvConfig` field (vanilla rules, harness, sensor, host), which decide what each field may be at evaluation. (Lesson 01, added 2026-11-25 after ADR 0006)
- **`final_obs_fresh`**: an `info` key on every step saying whether the returned observation is the true current state (False after death or level exit, when the previous one is repeated). (Lesson 01, added 2026-11-25 after ADR 0007)
- **Frame skip**: how many tics one decision is held for; ours is 4, so the agent decides 8.75 times per second of game time. (Lesson 01)
- **GAE (generalized advantage estimation)**: estimating the advantage as a weighted sum of future TD errors, with weights shrinking by γλ per step and cut at episode ends. (Lesson 06)
- **Game variable**: a number the engine reports each frame, such as HEALTH, ARMOR or POSITION_X. (Lesson 01)
- **Gap**: the number of steps between a cue and the moment it must be used. (Lesson 09)
- **Gate**: in a GRU, a set of numbers between 0 and 1, computed from the input and the old state, that decides how much to keep or replace. (Lesson 05)
- **Gate A**: ADR 0008's trainer-correctness test on the toy (gap 4, 100 updates, 8 seeds, all at least 0.95); it blocks DOOM training if it fails, and it passed 8 of 8. (Lesson 09)
- **God-view**: data that covers the whole level, not only what the player can see right now; the agent must never receive it. (Lesson 01)
- **Gradient**: for each weight, the direction and size of change that would increase the loss fastest; training moves weights the other way. (Lesson 07)
- **Gradient norm (`grad_norm`)**: the overall size of the gradient over all weights together; logged before it is clipped to 1.0, so values above 1.0 can appear. (Lesson 11; first used in Lesson 07)
- **Gradient-norm clipping**: scaling the whole gradient down when its overall size exceeds a limit (ours is 1.0), so one wild minibatch cannot make a huge step. (Lesson 07)
- **GRU (gated recurrent unit)**: a standard recurrent layer that updates its hidden state each step using a reset gate and an update gate; ours has 256 numbers. (Lesson 05)
- **Guard (reward)**: a rule inside the reward computation that stops one exploit, such as the episode cap; it never reads or changes the action. (Lesson 12)
- **Gymnasium**: a Python library that defines the standard shape of an RL environment, with `reset()` and `step()` methods. (Lesson 01)
- **Gymnasium wrapper**: an object that sits around an environment, passes `reset` and `step` through to it and may change what comes back; `ShapedRewardEnv` is one. (Lesson 12)
- **Harness**: the judges' evaluation program, which decides things like the maps, skill and time limit; our harness config fields (`maps`, `skill`, `episode_timeout_tics`, `map_wad`, `iwad_file`) describe what it may set. (Lesson 01)
- **Head**: one separate choice the network makes each decision; we have six (move, strafe, turn, attack, use, speed). Not to be confused with the attention heads inside the entity encoder. (Lesson 03)
- **Held-out map**: a map kept out of training on purpose and used only to test whether the agent works somewhere new. (Lesson 11)
- **Hidden state**: the numbers a recurrent network carries from one step to the next; our agent's memory, reset to zeros at each new episode. (Lesson 05)
- **High-water mark**: the largest value a counter has reached so far; the kill term pays only when the counter goes above it. (Lesson 12)
- **Horizon**: the screen row that looks straight ahead at eye level; ceiling is above it, floor below. Row 50 with the status bar on, row 60 with it off; the ray bands are measured from it. (Lesson 02; corrected 2026-11-25: bands now follow it)
- **HUD / status bar**: the strip at the bottom of DOOM's screen showing health, ammo and key icons; with it on, rows 100-119 of our 120-row image belong to it. (Lesson 01)
- **Inference**: using the trained network to play, with no learning; for us, a forward pass then sample or argmax per head. (Lesson 05)
- **`info`**: the dictionary returned beside each observation that holds privileged, training-only facts; it is never an input to the network. (Lesson 01)
- **Intrinsic reward**: reward for the agent's own behaviour, such as exploring, rather than for a game event. (Lesson 12)
- **IWAD**: the main DOOM data file holding maps, textures and monsters; we use the Freedoom files bundled with `vizdoom`. (Lesson 01)
- **JSON lines**: a text format with one JSON object per line; the training metrics file `metrics.jsonl` uses it. (Lesson 08)
- **KL divergence**: a measure of how different two probability distributions are, 0 when identical; `approx_kl` estimates how far one update moved the policy. (Lesson 07)
- **Label list**: the engine's list of objects drawn this frame, each with its on-screen box, labels-buffer value, `object_id`, class name and category. (Lesson 02)
- **Labels buffer**: a 120x160 image where each pixel holds a number naming the object drawn there, or 0 for no object. (Lesson 01)
- **Lambda (λ)**: the GAE weight (ours 0.95) that sets how far real rewards are trusted before switching to the value guess. (Lesson 06)
- **Launcher**: a small program that starts another with prepared settings; `configs/ops_launch.py` starts `train.run_doom` from a JSON file. (Lesson 10)
- **Layer normalization**: rescaling each token's numbers to average 0 and spread 1, then applying a learned scale and shift, to keep values in a stable range. (Lesson 04)
- **Layout guard**: the check that refuses more than one engine instance unless `--allow-multi-instance N` states the exact count. (Lesson 08)
- **Learner**: the training code that takes experience collected from the environment and updates the network's weights. (Lesson 01)
- **Learning curve**: how a result such as success rate changes over the course of training. (Lesson 11)
- **Learning rate**: how big each weight change is; ADR 0004 starts at 3e-4. (Lesson 07)
- **Line-of-sight filtering**: keeping only things the player could actually see; using labels gives this for free, because only drawn objects get a label. (Lesson 02)
- **Linear probe**: a separate small linear model trained to read one fact from a frozen network vector, to test whether the vector contains it. (Lesson 04)
- **Logits**: raw scores, one per option, that a softmax turns into probabilities. (Lesson 05)
- **Log-probability**: the natural log of a probability; the log-probability of a six-head action is the sum of the heads' log-probabilities. (Lesson 05)
- **Loss**: the number training tries to make smaller; ours is a weighted sum of policy, value, entropy and auxiliary terms. (Lesson 07)
- **LSTM**: a recurrent layer similar to the GRU, used in many published agents. (Lesson 05)
- **Map unit**: DOOM's basic unit of length in its levels. (Lesson 02)
- **Mask (attention)**: positions that must receive no attention weight; padded entity rows are masked. (Lesson 04)
- **Mean squared error (MSE)**: the average of (prediction - target) squared; the standard loss for predicting a number. (Lesson 07)
- **Measurement B**: ADR 0008's memory-capability test on the toy (gaps 20 and 60, 300 updates, pass = at least 7 of 8 seeds at 0.9); gap 20 passes, gap 60 fails. (Lesson 09)
- **Minibatch**: one part of the rollout used for one weight update; for us, all steps of 8 environments, kept as whole sequences. (Lesson 07)
- **MLP (multi-layer perceptron)**: a plain stack of fully connected layers. (Lesson 04)
- **Mod**: any change to the game made for training (cheat commands, map scripts, changed engine rewards, extra engine data); allowed in training, forbidden in final evaluation. (Lesson 01)
- **Modality dropout**: hiding telemetry from the network in a share of training episodes (flags set to 0) so it learns to cope without it; built but switched off in A0. (Lesson 06)
- **Modality flags**: three numbers in the observation saying whether telemetry is valid, whether the screen is present, and whether ego-motion is valid this step. (Lesson 02)
- **Monotonic**: always going the same way, never reversing (a monotonic rise never drops). (Lesson 11)
- **Multi-head attention**: several attention calculations side by side on slices of the numbers, so each can look for a different relationship. (Lesson 04)
- **MultiDiscrete**: a Gymnasium action description made of several separate whole-number choices, each with its own size. (Lesson 01)
- **Non-Markov reward**: a reward that depends on the past of the episode, not only on the current situation; the coverage bonus is one. (Lesson 12)
- **NO_READING**: the value 0.0 in a ray cell or entity distance, meaning "no valid depth pixel, no measurement"; real readings are at least 1/255. (Lesson 02, added 2026-11-25 after probe round 3)
- **Notifications buffer**: the text messages the game prints (for example "Blue passcard secured!"); we use it only for `info`, because at tic 1 it contains the level name. (Lesson 01)
- **Observation**: the data the agent receives about the current moment; for us, a dictionary of eight arrays, or seven when the screen is switched off. (Lesson 01; corrected 2026-11-25: the screen became optional)
- **Observation space**: the description of the observation's keys, shapes, types and ranges. (Lesson 01)
- **On-policy**: learning only from experience collected by the current version of the network; each rollout is used for one update, then discarded. (Lesson 06)
- **One-hot**: a list of 0s with a single 1 marking which option is chosen, such as which weapon slot is selected. (Lesson 02)
- **Optimizer**: the rule that turns gradients into weight changes; ours is Adam. (Lesson 07)
- **Padding**: all-zero rows that fill the fixed-size entity table when fewer than 24 things are visible. (Lesson 02)
- **Parameter**: one learned number in the network; the A0 model has 474,474. (Lesson 04)
- **Pass-through**: letting the scenario's own engine reward flow into the training reward unchanged (`engine_reward_scale` 1.0). (Lesson 12)
- **Per-engine rate**: decisions per second for one engine instance; it falls as more environments share one worker, because a worker steps them one after another. (Lesson 10)
- **Permutation invariance**: the output does not change when the input rows are put in a different order. (Lesson 04)
- **Pickling**: turning a Python object into bytes so it can be sent through a pipe or to a new process. (Lesson 08)
- **Pipe**: a two-way message channel between two processes. (Lesson 08)
- **Plateau**: a stretch of training where the learning curve stays roughly flat. (Lesson 11)
- **Policy**: the rule the agent uses to choose an action from an observation; for us, the neural network. (Lesson 01)
- **Policy path**: the code route from engine data to the observation the network sees (`_build_obs`), kept separate from the `info` route. (Lesson 01)
- **Positional encoding**: numbers added to each item to tell the network its position in a list; the entity encoder deliberately has none. (Lesson 04)
- **Positive control**: a version of an experiment that should succeed if the machinery works, used to tell a broken code path from a hard task. (Lesson 09)
- **PPO (proximal policy optimization)**: the policy-update method we use; it limits how much each stored action's probability can be pushed in one update by clipping the probability ratio. (Lesson 07)
- **Preset (reward)**: a named, ready-made set of reward settings in `configs/reward_config.py`, such as `MY_WAY_HOME_REWARD`. (Lesson 12)
- **Priority (below normal)**: how much the operating system favours a process; below normal means it runs when the user's programs do not need the CPU. (Lesson 08)
- **Privileged information**: facts from the engine's god-view or that would identify a map (absolute position, map name, whole-level object lists); allowed in `info` for training, never in the observation. (Lesson 01)
- **Probability distribution**: a rule giving how likely each option is; probabilities are positive and sum to 1. (Lesson 05)
- **Probability ratio**: a stored action's probability under the network now divided by its probability when it was taken; 1 before any update. (Lesson 07)
- **Process**: a running program with its own memory; Python is one process, each `vizdoom.exe` another. (Lesson 08)
- **Process tree**: a process together with all its children, grandchildren and so on. (Lesson 08)
- **Proprioception**: the body's sense of its own motion and state, as opposed to sensing the outside world. (Lesson 02)
- **Pure function**: a function whose output depends only on its inputs and that changes nothing outside itself. (Lesson 02)
- **PWAD**: an add-on DOOM map file loaded on top of the IWAD; it may carry ACS scripts, so it is training only. (Lesson 01)
- **Rays**: our (3, 80) array of nearest distances, one per row band and 2-pixel column slice of the view, taken from the valid pixels of the depth buffer; 0.0 means no reading. (Lesson 02; corrected 2026-11-25: weapon and other depth-0 pixels are now excluded)
- **Recurrent**: a network that feeds part of its own output (the hidden state) back in at the next step. (Lesson 05)
- **ReLU**: a function that keeps positive numbers and turns negative ones into 0, used between layers. (Lesson 04)
- **Reset**: the environment call that starts a new episode and returns the first observation and `info`. (Lesson 01)
- **Resident memory (RSS)**: the memory a process is really using right now; the run loop sums it over the whole process tree. (Lesson 08)
- **Residual connection**: adding a layer's input back to its output, so the layer only learns a change. (Lesson 04)
- **Resume**: load a checkpoint and continue training; ours refuses a checkpoint whose sensor signature, model config or observation spec differs. (Lesson 08)
- **Retention time (τ)**: how many steps a GRU unit roughly keeps its value; with update gate z, τ = 1 / (1 - z). (Lesson 09)
- **Return**: the total (discounted) reward from a moment onward. (Lesson 06)
- **Return scale (`return_scale`)**: the number value targets are divided by: the running standard deviation of all returns seen since the start of the run, never below 0.1. (Lesson 11; first used in Lesson 06)
- **Reward**: a number telling the agent how good the last action turned out; learning tries to make the total large. (Lesson 01)
- **Reward hacking (exploit)**: the agent finding a way to collect reward without doing what we wanted, such as spinning on the spot for an exploration bonus. (Lesson 12)
- **Reward shaping**: extra reward terms we design ourselves to guide learning, used in training only. (Lesson 01)
- **Rollout**: a fixed stretch of collected experience (64 decisions from each environment) stored for one update. (Lesson 06)
- **Seed**: a number that fixes a random number generator, so a run can be repeated exactly. (Lesson 01)
- **Self-attention**: attention in which the items of one set look at each other. (Lesson 04)
- **Sensor signature**: the list of sensor settings (frame skip, status bar, turn bins, entity cap, screen on/off, ray bands) that must be identical between training and evaluation. (Lesson 01, added 2026-11-25)
- **Session**: one stretch of training between a start or resume and a stop; each resumed session gets a new environment seed. (Lesson 08)
- **Signal handler**: a function a program runs when the operating system delivers an event such as Ctrl-C. (Lesson 08)
- **Smoke test**: a quick check that catches large mistakes but does not prove correctness. (Lesson 01)
- **Softmax**: the function that turns a list of logits into probabilities that are positive and sum to 1. (Lesson 05)
- **Spawn**: the way Windows starts a Python child process: a fresh interpreter that re-imports the modules it needs. (Lesson 08)
- **Standard error**: how much an average would typically change if the measurement were repeated with different random luck; for a success rate p over n episodes about the square root of p(1-p)/n. (Lesson 11; first used in Lesson 10)
- **Step**: the environment call that applies one action for one decision (4 tics) and returns observation, reward, terminated, truncated and `info`. (Lesson 01)
- **Stride**: how many positions a convolution window moves at a time; stride 2 halves the length. (Lesson 04)
- **Success rate**: the share of episodes that ended at the goal (`success`, equal to `level_exit`). (Lesson 11)
- **Synchronous**: collecting experience and updating the network in turns, so collection pauses during each update. (Lesson 06)
- **TD error (temporal-difference error)**: reward plus the discounted value of the next situation, minus the value of the current one; one step of "better or worse than expected". (Lesson 06)
- **Telemetry**: numbers taken directly from the engine instead of from pixels; for us, rays, entities and ego-motion. (Lesson 02)
- **Terminated**: the end-of-episode flag meaning the game itself ended (death or level exit). (Lesson 01)
- **Thread**: a second line of work inside one process; the memory watcher runs as one. (Lesson 08)
- **Tic**: one tick of DOOM's internal clock; the game runs at 35 tics per second of game time. (Lesson 01)
- **Time-out rate**: the share of episodes that ended because the time limit ran out. (Lesson 11)
- **Timer request**: asking Windows for a 1 ms system clock so waits for the engine are not rounded up to 15.6 ms; on for TRAIN, off for EVAL. (Lesson 01, added 2026-11-25)
- **Token**: a fixed-size vector standing for one item; the entity encoder makes one 64-number token per visible entity. (Lesson 04)
- **Trace**: how much a past input still changes the hidden state now; the cue trace at step 20 was 1.3e-6 at initialisation. (Lesson 09)
- **TRAIN config**: `TRAIN_CONFIG`, the training settings; now the bundled `my_way_home` scenario with the same sensors as EVAL, and mods allowed. (Lesson 01; corrected 2026-11-25: was freedoom2 MAP01-MAP03)
- **Transformer**: a network built from stacked attention layers, often run over a long sequence of past inputs. (Lesson 04)
- **Truncated**: the end-of-episode flag meaning we stopped the clock (time limit) while the game could have continued. (Lesson 01)
- **Update gate (z)**: the GRU gate that decides, per unit, how much of the old hidden state to keep each step (h_new = (1 - z) * n + z * h); about 0.5 at initialisation. (Lesson 09)
- **Value**: the network's guess of the total discounted future reward from the current situation; used in training, not to choose actions. (Lesson 05)
- **Value target**: what the value head is trained toward: advantage plus the stored value (the GAE return estimate). (Lesson 06)
- **Vanilla**: the standard, unmodified game and rules, which final judging uses. (Lesson 01)
- **Vectorized environment**: several environments stepped together with one batch of actions; `SyncVecEnv` steps them in one process, `SubprocVecEnv` in worker processes. (Lesson 06; corrected 2026-11-25: worker version added)
- **`+viz_nocheat`**: a ViZDoom setting that, as our probe measured, removes the depth buffer, labels buffer and label list and zeroes position, angle and velocity. (Lesson 02)
- **Void comparison**: a comparison whose setup makes it unable to show what it was meant to test, for example against a base already at the maximum score. (Lesson 10)
- **`weights_only=True`**: the safe way to load a checkpoint in PyTorch, accepting only tensors, numbers, strings, lists and dicts, so loading cannot run hidden code. (Lesson 08)
- **Window (episode window)**: a block of consecutive finished episodes (here 500) whose results are averaged together. (Lesson 11)
- **Worker process**: a child process whose only job is to run some environments and report back; ours never import torch. (Lesson 08)
